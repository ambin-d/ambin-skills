# 错误教训固化与预防

## 触发条件
- 用户明确指出我做错了、教过我、重复犯
- 任务执行失败或验证不过
- 每日复盘发现同类错误

## 执行步骤
1. 立即停下手头事，先简短复述用户指出的错误，不辩解、不找借口
2. 按三段式固化教训（格式与 agent-retro 完全统一，见下）
3. 写入记忆库：type=failure_lesson，带 cue（触发关键词），带评分
4. 同步追加一行到 Vault 固化文件：`<VAULT>\06-复盘与日志\Agent A复盘\错误教训库.md`（周报数据源，避免记忆库统计不到）
5. 若同一 cue 已有教训存在：升级为重复错误警告，评分 +1，并在回复中主动承认"这是第 N 次犯同类错误"

## 教训模板（与 agent-retro 三段式完全一致，缺一不可）
```
**🔴 [错误标题]**
问题：[当时我做了什么/说了什么，客观描述]
原因：[机制层面的根因，不是"我粗心"这种废话]
后果：[导致了什么后果，链式影响写清楚]
→ **教训**：[一句话，带触发场景——什么时候/做什么操作前该想起这条]
🔁 重复：[是/否] — [如重复注明上次犯的日期]
✅ 验证动作：[报告/行动前必须执行的可验证检查，如查 LastTaskResult、看日志完成行、复测三遍]
```

## 硬规则
- 每条教训必须有可执行的验证动作，纯口号不固化
- 报告"完成/正常"前必须执行验证动作（如查 LastTaskResult、看日志完成行、复测三遍）
- 固化的时机是当场，不是等复盘——复盘只负责查漏和统计重复率
- 用户纠错时优先级最高：先固化教训，再继续其他任务

## 验证
- 每次复盘（Agent Retro）时按 cue 检查近期行为是否重复触发已固化的教训
- 触发次数 ≥2 的教训必须升级为红色警告并在周报中列出
- 每周进步周报从 `错误教训库.md` 统计本周新错误数/重复犯次数
