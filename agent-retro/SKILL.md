# Agent Retro v2.0 (进化版复盘行动 SOP)

> **进化来源：** 2026-07-13 分析 Agent B daily-review-manager + Agent B自我进化体系 后融合升级。
> 核心改进：① 守则执行检查表 ② 重复错误警告 ③ 教训三段式 ④ 守则库持续累积 ⑤ 待办追踪 ⑥ 自评分 ⑦ 周报/月报模板 ⑧ 每周进步周报（自动推送，数据对比）⑨ 承诺兑现率（落地监督台账集成）
> **2026-08-05 用户需求：** 每周必须看到「吸取教训后的进步总结」，进步必须明显、真实、可量化。error-lesson 与 agent-retro 定为重点技能。光说不练必须杜绝——周报同时核对「承诺兑现率」。
> **2026-08-05 Agent B复查建议已采纳：** `06-复盘与日志/每日复盘.md` 为Agent A/Agent B共享文件，双方只读它做数据源，不修改对方段落，各自内容只进各自专属目录（Agent A复盘/、Agent B复盘/）。防未来误写。（见行为约束 12）

本技能定义了 Agent 每日复盘的标准操作程序。执行复盘时，必须严格按照以下步骤进行。

## 执行要求

* 改动所有文件之前，都需要先备份。
* 例如改动 `SKILL.md` 之前，要先复制一份命名为 `SKILL.md.bak.${yyyyMMddHHmmss}`，作为备份，再进行修改。
* 复盘报告写入 Vault 时必须用 **Set-Content -Encoding UTF8**，写入后用 Get-Content 读前几行验证中文正常显示。

## Step 0: 历史复盘回溯（新增）

**写复盘前必须先读历史。** 不读历史就写复盘 = 不长记性。

1. 读取 Vault 中 `06-复盘与日志/Agent A复盘/` 目录下所有历史复盘文件（尤其是最近的 7 天）
2. 提取三个核心要素：
   - **守则库** — 之前累积的所有改进措施/守则的列表
   - **重复错误历史** — 已出现过 2 次以上的同类型错误
   - **待办追踪** — 至今未完成的跨天待办
3. 把这些信息加载到当前记忆，作为今天写作的前置知识

**判断标准：** 打开复盘文件后，先问自己一句"上次犯过的错，今天又犯了吗？"

---

## Step 1: 确定时间与范围

1. 确定复盘的 Agent ID（默认情况为 `main`）。
2. 确定目标日期（格式 `YYYY-MM-DD`）。如果用户说"昨天"，根据当前本地时区准确推算昨天的日期。
3. **检查复盘锁**：根据目标日期构造锁文件路径（例如目标日期为 2026-02-04，则锁文件为 `memory/AGENT_RETRO_DONE_20260204.md`）。如果存在，**立即终止复盘**并告知用户。

---

## Step 2: 收集历史数据

1. 读取Agent A的 conversation history 和 action log，找到目标日期的所有交互记录。
2. 提取当天的所有：用户指令、Assistant 回复、工具调用（Tool Calls）及工具结果。
3. 如有可能，读取 Vault `06-复盘与日志/Agent A复盘/` 中用户对该日提出的反馈（如有批评/夸赞）。

## Step 3: 守则执行检查 + 6 维度分析（升级版）

### 3.1 守则执行检查（新增）

从守则库中逐条读取历史守则，对照当天的行为进行检查：

| 守则 | 执行 | 改进 | 备注 |
|------|:----:|:----:|------|
| [守则1] | ✅/❌/➖ | [如违反则写怎么改进] | [说明] |
| [守则2] | ✅/❌/➖ | [如违反则写怎么改进] | [说明] |

标记规则：
- ✅ = 今天守住了这条守则
- ❌ = 今天又犯了这条守则 → **必须标记为重复错误！！**
- ➖ = 今天没涉及这条守则

**如果今天犯了以前已经犯过的错 → 在报告中加 ⚠️ 重复错误警告，并注明上次犯的日期。**

### 3.2 6 维度总结（保留原有）

根据提取的聊天记录，总结以下 6 个维度的内容：

* **昨日动作**：昨天做了哪些事情。
* **做对的事情**：一次完成没有重复对话，或者获得了用户的称赞的事项。
* **做错的事情**：没有一次完成，陷入重复修正，或者被用户批评的事项。**每条错误必须用教训三段式格式。**
* **改进点**：针对做错的事情，提出具体的、可执行的防范改进点（不是"以后注意"，而是具体的步骤/流程/命令）。
* **用户画像**：用户是一个什么样的人（偏好、风格、底线等）。
* **Agent 画像**：你是一个什么样的 Agent（暴露出的行为倾向或缺陷）。

### 3.3 教训三段式格式（新增）

每条错误必须按如下格式记录：

```
**N. 🔴 [错误标题]**
行为：[做了什么具体操作]
后果：[导致了什么后果，链式影响写清楚]
→ **教训**：[一句话，刻进骨子里那种，可执行的改进步骤]
🔁 重复：[是/否] — [如果重复，注明上次犯的日期]
✅ 验证动作：[具体场景复现时怎么确认这条教训已生效/未复发]
```

**每条错误都必须有「行为→后果→教训」三段式。** 不记错的复盘是汇报，不是复盘。

## Step 5: 更新核心配置（核心步骤）

1. **对比更新 MEMORY.md**：提取 Step 3 中的关键结论，与工作区下的 `MEMORY.md` 做对比。新增缺失的结论，修改过时的结论。
2. **更新 USER.md**：使用 Step 3 提炼的"用户画像"信息，修改 `USER.md`，完善上下文。
3. **更新 SOUL.md**：使用 Step 3 提炼的"Agent 画像"信息，修改 `SOUL.md`，强化核心性格与行为边界。
4. **更新 AGENTS.md**：使用 Step 3 提炼的"改进点"，修改 `AGENTS.md` 中的工具约束或战术准则，确保教训被固化。

## Step 6: 向用户推送复盘报告（优先于写锁）

在确认所有文件都已成功更新落盘后，通过 send_message 向用户推送复盘概要。
报告内容应简明扼要，说明：总览、守则执行情况（✅❌比率）、核心问题、新增守则、自评分。

**推送完成后再写锁文件。**

## Step 7: 写入复盘锁（天级别防重复）

推送完成后，写入复盘锁文件 `memory/AGENT_RETRO_DONE_YYYYMMDD.md`。
锁文件存在 = 推送已完成。下一次复盘检查到锁文件直接跳过。

## Step 8: 每周进步周报（每周日 21:00 自动生成并推送微信）

> **2026-08-05 用户硬性要求：** 「每个礼拜看到相关汇报，汇报要关于吸取教训后这周到下周进步在哪里、进步了什么，要看到明显的真实的进步。」
> **2026-08-05 补充要求：** 光说不练必须杜绝——周报必须同时核对承诺兑现率（落地监督台账）。
> **原则：** 周报不是流水账，是进步证据。没数字、没对比、没具体案例 = 不合格。

### 触发方式
- **自动触发：** 每周日 21:00 提醒（reminder #41）触发后执行本步骤。
- **手动触发：** 用户说「周报」「每周进步」时执行。

### 执行流程

1. **读本周复盘**：读取 `<VAULT>\06-复盘与日志\Agent A复盘\` 最近 7 天（本周一~周日）的所有复盘文件，同时读上周的周报（`_每周进步周报.md` 或上周日文件）拿对比基线。
2. **读承诺落地台账**：读取 `<VAULT>\06-复盘与日志\Agent A复盘\承诺落地台账.md`，统计本周新增承诺数、已落地数、进行中数、未完成数。
3. **统计本周数据**：
   - 本周新错误数（error-lesson 固化条数）
   - 本周重复犯次数（🔁 重复=是 的条数）
   - 已闭环项（本周有验证动作确认未复发的教训）
   - 本周做对的事、新增守则、待办进展
4. **对比上周**：每个指标与上周对比，标趋势（↓进步 / →持平 / ↑退步）。
5. **写周报文件**：追加写入 `<VAULT>\06-复盘与日志\Agent A复盘\_每周进步周报.md`（Set-Content -Encoding UTF8，写完读回验证）。
6. **推送微信**：send_message 推送周报给用户（ID:000001）。

### 周报固定格式（推送内容）

```
━━━ 📊 每周进步周报（本周一 ~ 周日）━━━

### 1️⃣ 本周数据
- 新错误：N 条 | 重复犯：N 次 | 已闭环：N 条
- 闭环率：X%（上周 Y%）
- 承诺兑现：本周承诺 N 项 | 已落地 N 项 | 兑现率 X%（上周 Y%）

### 2️⃣ 本周 vs 上周

| 指标 | 上周 | 本周 | 趋势 |
|------|:----:|:----:|:----:|
| 新错误数 | A | B | ↓/→/↑ |
| 重复犯次数 | C | D | ↓/→/↑ |
| 闭环率 | E% | F% | ↑/→/↓ |
| 承诺兑现率 | G% | H% | ↑/→/↓ |

### 3️⃣ 进步点总结（必须有具体证据）
每条进步点格式：**教训X → 本周场景Y复现，未再犯 ✅**（或：本周首次做到 Z）
- 进步点1：...
- 进步点2：...

### 4️⃣ 还没做好的
- [退步项/未闭环项/未兑现承诺] → 下周具体动作：[怎么做]

### 5️⃣ 下周目标
1. [1-2 条具体可验证目标，下周周报逐条核对]

━━━━━━━━━━━━━━━━━━━━━
```

### 周报硬性要求
- ❌ 禁止写「本周总体表现良好」这类空话。
- ✅ 每个进步点必须能对应到具体教训和具体场景（证据），或本周首次做到的实事。
- ✅ 重复犯次数上升时必须诚实标红，写清楚原因和下周动作。
- ✅ 承诺兑现率 <100% 时必须列出未落地/未兑现清单，写明卡在哪、下周动作。
- ✅ 下周目标必须可验证（能用「做到了/没做到」判断）。

## Step 9: 月报（新增能力）

用户说"月报"时，汇总当月复盘记录：

- 错误趋势（总错误数 ↓↑ vs 上月）

## 数据来源（cron 运行专用）

⚠️ cron 运行时无法读取微信对话历史。需要从以下路径读取：

1. **`06-复盘与日志/Agent A复盘/`** — 所有历史复盘记录（含守则库、重复错误、待办、周报、承诺落地台账）
2. **`06-复盘与日志/每日复盘.md`**（如存在）— 用户每日复盘报告（⚠️ 共享文件，只读，不修改对方段落）
3. **`07-智能体协作/交流记录/`** — 与Agent B的协作留言
4. **`07-智能体协作/任务队列/`** — 任务队列状态

## 行为约束

1. **复盘的第一件事是回头看历史复盘，不是从头开始写。** 不读历史就写复盘 = 不长记性。
2. ❌ **错误/教训部分是复盘的核心** — 每条错误都必须有「行为→后果→教训」三段式。
3. 🔁 **重复错误必须标红警告**，注明上次犯的日期，形成压力。
4. ✅ 改进措施必须**可执行**（具体命令/流程/步骤），不写"以后注意"。
5. ⏳ 待办记录**首次出现日期**，追踪跨期待办。
6. ⭐ 每次复盘末尾追加**自评分（1-5）+ 理由**，积累后自动发现共性问题。
7. 报告落盘用 **Set-Content -Encoding UTF8**，写完后必须读取验证中文正常显示。
8. **先推送后写锁**，锁文件存在 = 推送已完成。
9. ⭐ **error-lesson 与 agent-retro 为重点技能，优先保证闭环**：当场固化 → 复盘复查 → 重复犯升级警告 → 周报展示进步。此线优先于其它技能。
10. 📊 **每周日必须推送《每周进步周报》**，数字+对比+具体案例，空话周报视为未完成。
11. 📌 **承诺必须入账**：任何对用户的承诺都写入 `承诺落地台账.md`，兑现率进周报。向用户说"已完成"前先核对台账证据（落地监督 skill）。
12. 📌 **共享文件只读规则**（2026-08-05 Agent B复查建议采纳）：`06-复盘与日志/每日复盘.md` 为Agent A/Agent B共享文件，双方只读它做数据源，不修改对方段落；各自内容只进各自专属目录（Agent A复盘/、Agent B复盘/）。防未来误写。
